> 클로드코드(클라우드)는 리포까지만 손댈 수 있다. 아래는 **원장 PC의 clasp가 있어야 붙는 것들**이다.

## 공통 규칙 (전 작업)

- 착수 전 `git pull` (acro·acro_canon 둘 다).
- 배포는 **기존 배포ID `-i` 재배포**. 신규 배포 절대 금지 — 새 URL이 생기면 라인 리치메뉴·QR·
  카톡 저장링크가 전부 끊긴다. 착수 전 `clasp deployments`로 개수를 적어두고, 배포 후 같은지 확인.
- 토큰·URL·배포ID 값은 **화면 출력·커밋 금지**. 속성에 직접 붙여넣는다.
- DB는 **SELECT만**. 차트 INSERT/UPDATE는 어떤 경로로도 금지.
- 실패·거부·빈 응답은 전부 조용히 넘기고 사람에게 인계. 환자에게 오류를 노출하지 않는다.

## 0순위 — 응대가 말을 끝내지 않는다 / 방금 들은 걸 또 묻는다 (원장 지적 260822)

두 증상은 원인이 다르다. **따로 고친다.**

**① 말이 중간에 끊긴다** — 출력 상한(`max_tokens`)에 걸린 것이다. 일본어는 같은 내용도
토큰을 많이 먹어서 한국어보다 훨씬 빨리 상한에 닿는다.

- 지금 실제로 응대하는 **기존 브릿지 호출부**(`instant_reply.gs` / `Code.gs` / `mcNightGate_`)의
  `max_tokens` 값을 찾아라. **1200 이하면 그게 원인이다** — 2000으로 올린다.
- 더 중요한 것: 응답 JSON의 `stop_reason`이 `'max_tokens'`면 **그 답은 보내지 않는다.**
  끊긴 안내는 안 보낸 것보다 나쁘다(용법·부작용 문장 중간에서 끊기면 사고다). 사람에게 넘긴다.
- acro `gas/claude_call.gs`는 260822에 이 두 가지가 이미 반영돼 있다(상한 2000 + 절단 시 null).

**② 방금 말한 걸 또 묻는다** — 기억이 없어서다. 매 메시지가 그 환자와의 첫 대화로 처리된다.
처방은 1.5순위(`gas/patient_memory.gs`)다. **0순위에서 할 일은 없고, 1.5순위를 앞당기라는 뜻이다.**

**③ "생각을 하고 대답해야 하는데"** — 추론 강도가 `low`다(지연을 줄이려고 그렇게 잡았다).
`claude_call.gs`는 속성 `ACC_EFFORT`를 `medium`으로 두면 코드 수정 없이 올라간다.
**①②를 고친 뒤에도 겉도는 답이 남을 때만** 올린다 — 지연이 늘어나므로 마지막 수단이다.

## 1순위 — 발송 전 관문 (오늘 지적된 사고를 막는다)

**왜 먼저인가**: 원장 실사용 지적 260820 — ① 중복으로 대답함 ② 일본 환자에게 강남언니
한국 링크·한국 블로그를 보냄. 지금 이 순간에도 재발 가능한 사고다.

**파일**: `gas/reply_guard.gs` → 라인브릿지 프로젝트에 추가.

**배선 지점**: 환자에게 메시지를 **보내기 직전** 한 곳.

```js
var g = argCheck_(보낼텍스트, 채널키 /* 'jp' | 'tw' | 'ko' */, 메시지ID);
if (!g.send) {           // 중복이거나, 대체 불가한 한국어 전용 자산이 실림
  // 환자에게 보내지 않는다. 사유(g.reason)는 원내 채널에만 남긴다.
  return;
}
sendToPatient(g.text);   // g.text는 언어판으로 교체됐을 수 있다 (g.swapped 참조)
```

- `메시지ID`는 **LINE 웹훅 이벤트의 `webhookEventId`** 를 그대로 넘긴다(라인 공식 문서가 중복
  판정에 이 값을 쓰라고 안내한다). **못 넘기면 중복 차단이 안 된다** — id가 없으면 막지 않도록
  설계돼 있다(정상 응대를 삼키는 쪽이 더 나쁘므로).

**⚠ 연속 답변의 진짜 원인 (실측 진단 260820)** — 원장 라인 테스트에서 AI가 연달아 답했다.
원인은 AI가 수다스러운 것이 아니라 **같은 질문을 여러 번 받은 것**이다:
라인은 웹훅 후 **2초** 안에 200을 못 받으면 실패로 보고, 재전송 설정이 켜져 있으면 같은 이벤트를
다시 보낸다. GAS에서 AI 답변을 만드는 데 2초를 훌쩍 넘기므로 매번 타임아웃 → 재전송 → 중복 응답.

조치는 셋이고, 순서가 있다:
1. **(원장 몫·미완)** LINE Developers Console → 채널 → `Messaging API` 탭 → Webhook settings →
   **`Webhook redelivery` OFF.** (바로 위 `Use webhook`은 절대 끄지 말 것 — 응대가 통째로 멈춘다.)
   같은 화면 Error statistics에 `request_timeout`이 쌓여 있으면 확진.
   ※ 260820 시점 원장이 콘솔 접근 불가로 **보류 중** — 배선 세션이 대신 할 수 있으면 먼저 할 것.
2. `argCheck_`에 `webhookEventId`를 넘긴다 — 재전송이 와도 두 번째는 발송하지 않는다.
3. **(정석·손이 더 감)** doPost가 웹훅을 받자마자 200을 반환하고 답변 생성은 그 뒤에 한다.
   이러면 애초에 타임아웃이 안 나므로 1·2가 없어도 된다. 여유 될 때 이쪽으로 간다.
- 채널키는 브릿지가 이미 쓰는 값(`jp`/`tw`)을 그대로. 한국 채널은 게이트가 자동 통과시킨다.

**검증 3개**
1. 일본 채널에서 네이버 블로그 링크가 든 답변 → **아메블로 링크로 바뀌어 나가는지**
2. 같은 메시지를 두 번 처리시켜 → **두 번째는 발송 안 되는지**
3. 일본어판 없는 글(두드러기·색소성 양진, 네이버 223253617836) → **발송 멈추고 사유가 남는지**

## 1.5순위 — 환자 기억 (260820 실측 사고 처방 + 원장 지시 "직원을 배우자")

**왜**: 원장 라인 테스트(J003)에서 ① AI가 자기 발화를 환자 발화로 착각("4시 원하신다고

대화 이력을 화자 라벨 없이 통짜로 주입하는 방식이다.

**파일**: `gas/patient_memory.gs` → 라인브릿지에 추가. 속성 `APM_SHEET_ID`(메모 시트 —
인입원장 스프레드시트 등 원내 시트 ID, 커밋 금지). 설계 정본: 재설계 v1.8 §2.9.

**⚠ 260822 갱신 — 이력을 직접 만들지 마라. 이미 다 있다.**
원장 지시로 슬랙·인입원장을 실측한 결과, 필요한 재료가 전부 이미 쌓이고 있었다:

| 있는 것 | 어디 | 확인 |
|---|---|---|
| 대화 전문(환자·AI·직원) | 슬랙 환자 **카드 스레드** | #cs_fn_일본_라인 J148·J153 실측 |
| userId → 채널·번호·**스레드ts** | 인입원장 `라인환자맵` D열 | 헤더 실측 |
| 연속성 메모 | 인입원장 `환자메모` | `jp#J153 … 16:31` 이미 쌓이는 중 |

그래서 `apmHistoryFor_(userId)` 한 줄이면 끝난다. 턴 배열을 손으로 만들지 말 것.

**배선 3지점**:
1. 응답 생성 전 —
   ```js
   var key  = apmKeyFor_(userId);              // 'jp#J153'
   var hist = apmHistoryFor_(userId);          // 슬랙 스레드 → 화자 라벨 붙은 최근 10턴
   var mem  = apmContextBlock_(apmLoadMemo_(key), hist);
   ```
   `mem`을 `accAsk_(작업지시, KB히트, 환자메시지, mem)`의 4번째 인자로 넘긴다.
   **기존의 통짜 스레드 주입은 제거한다** — 이게 사고 원인이므로 병행 금지.
2. 발송 후 — `apmUpdateMemo_(기존메모, 이번 대화)` → 성공 시 `apmSaveMemo_(key, …)`. 실패 무시.
3. 화자 판정은 `apmClassify_`가 한다(슬랙 실측 표식 기준). **손으로 고치지 말 것** —
   판정 기본값이 '기록'인 이유가 260820 사고다: 모르는 메시지를 환자로 찍으면 AI가
   자기 말을 환자 말로 착각한다.

**추가 속성 3개**: `SLACK_BOT_TOKEN`(이미 있으면 그것) · `APM_SLACK_CH_JP` · `APM_SLACK_CH_TW`
(각 채널ID). 값은 화면 출력·커밋 금지. 봇에 `channels:history` 읽기 권한이 있어야 한다 —
없으면 `apmHistoryFor_`가 조용히 `''`를 돌려주고 응대는 평소대로 돈다(안전판).

**(추가 260822) 직원이 적은 차트번호 줍기.** 실측: 직원들은 이미 스레드에
"차트 20193 GIMAMIYUKI"라고 적고 있는데 **아무 데도 안 들어간다.** 환자맵 140행 중
차트번호가 있는 건 34행(24%)뿐이고 그것도 전부 표시이름 자동매칭이다. 사람이 알아낸

슬랙 Events 처리에서 **스레드 답글이면** 한 줄 추가:
```js
var c = apmNoteChartFromThread_(event.thread_ts, event.text);
if (c) postToThread('📇 ' + c.no + ' → 차트 ' + c.chart + (c.name ? ' ' + c.name : '') + ' 기록');
```

## 1.6순위 — 원장 실측 피드백 2건 (260820 밤, 작음·빠름)

**(a) 환자맵 자동매칭 규칙 확장.** 현재 규칙은 "displayName이 숫자로 시작하면 차트번호로
자동매칭"(예: `20138NAKASE AIRI`). 그런데 `#22 임주혁` · `[#22 임주혁]`처럼 **#가 앞에 붙는
표기가 실사용에 있다** — 원장 계정이 이 때문에 매칭 안 됐다. 규칙을 "선행 `[`·`#`·공백을
벗긴 뒤 숫자로 시작하면 그 숫자를 차트번호로"로 확장하고, 자릿수는 환자맵 기존 표기에 맞춰
제로패딩(예: 22 → 000022 — **실제 차트번호 자릿수를 시트에서 확인 후 맞출 것, 추측 금지**).

**(b) 예약판(날짜) 질문은 본인확인이 필요 없다.** "내일 진료 가능한 시간이 언제인가요?"는
특정 환자의 차트를 여는 게 아니라 **날짜 기준 예약판 조회**다 — 개인정보 게이트 대상이
아니다. 현재 브릿지는 환자 단위 조회(patient_verify 등)만 배선돼 있어 시간 질문에
"확인 기능이 없다"로 후퇴했다(260820 원장 실측). 배선:
- 시간·예약 가능 질문 감지 → `acqFreeSlots_(날짜, 후보슬롯)` (내부적으로 `resv_list`).
  후보 슬롯은 **브릿지 기존 영업시간 모듈**이 만든다(§2.7 — 영업시간 재정의 금지).
- 선행: 워커에 `resv_list` 등록(정의 `okchart/named_queries.md`).
- null(조회 실패·야간)이면 슬롯 제시 금지 — "직원 확인 후 안내"(§2.7 그대로).
- 제시 문구는 "기존 예약이 없는 시간대" 수준 — 확정은 직원(§2.7 "요청 접수" 원칙 유지).

**(c) lwWorker_ 상태 1줄 보고.** 원장 관찰: 실행 로그에 lwWorker_가 계속 돈다. 정상 여부
판단 기준으로 다음을 보고할 것 — ① 트리거 주기 ② 회당 평균 실행시간 ③ 하루 합산
실행시간(GAS 트리거 한도 대비) ④ 오류율 ⑤ 유휴 틱에서 UrlFetch를 몇 번 하는지(0이어야 정상).

## 3순위 — 주간 즉답 + 이어받기 (`^` 토글)

**파일**: `gas/line_handoff.gs` (이미 로컬에서 `instant_reply.gs`에 결합됨 — 상태 확인 후 진행).

**남은 것은 슬랙 Events URL 등록**(원장 몫) — api.slack.com → 해당 앱 → Event Subscriptions에
브릿지 `/exec` 주소 + `?src=slack&k=KEY`. 등록 전에는 `^`도 자동 홀드도 전부 죽어 있다.

**등록 전에 코드에 반드시 넣을 가드 2개** (안 넣으면 환자에게 중복 발송된다):
- `X-Slack-Retry-Num` 헤더가 있으면 즉시 200만 반환하고 무시 (슬랙은 3초 내 응답 없으면 재전송)
- `subtype === 'bot_message'` 또는 `bot_id`가 있으면 무시 (자기 미러링이 되돌아와 루프)

**명령 체계** (원장 확정 260814):

| 입력 | 동작 |
|---|---|
| 표시 없는 글 | 아무 일도 안 일어남 (내부 메모) |
| `!텍스트` | 번역해서 환자 발송 (기존 관례) + AI 자동 멈춤 |
| `!!텍스트` | 번역 없이 환자 발송 (기존 관례) + AI 자동 멈춤 |
| `^` (정확히 한 글자) | AI 온오프 토글 — **결과를 스레드에 "⏸ AI 멈춤"/"▶ AI 재개" 1줄로 답할 것(필수)** |

**검증**: `^` 왕복 1회(멈춤→재개)가 확인되기 전에는 DAY_AI를 켜지 않는다.
끄는 버튼이 없는데 자동 발송을 켜는 것은 안전판 없이 켜는 것이다.

## 4순위 — 응대 속도 (캐싱)

**파일**: `gas/claude_call.gs` → 각 접점의 클로드 호출을
`accAsk_(작업지시, KB히트, 환자메시지, 기억블록)`로 교체.
**4번째 인자(기억블록)를 빼먹지 말 것** — 빼면 1.5순위에서 붙인 기억이 프롬프트에 안 실려
되묻기가 그대로 남는다. 1.5순위를 먼저 붙였다면 `apmContextBlock_(...)` 결과를 그대로 넘긴다.

- 조립 순서는 acro_canon 재설계 v1.7 **§2.2**가 기준. §2의 나열 순서로 조립하면 캐시가 매번 깨진다.
- **작업 지시에서 날짜·시각·환자 이름을 뺀다** — 그 한 줄이 캐시를 매일 깬다.
- 정본 등재 절차에 `accFlushPrefix()` 호출 추가 (누락 시 최대 6시간 옛 정본으로 응대).
- `ACC_FAST` 속성은 **켜지 말 것** — 단가 2배. 아래 실측 보고 후 원장 판단.

**검증**: 같은 접점에 연속 2회 질문 → 2회차 로그의 `cache_read`가 0이 아닐 것. **0이면 배선 오류이니
배포하지 말고 보고.**

**같이 하면 좋은 것**: LINE 로딩 인디케이터(응답 생성 중 표시). 체감 지연을 줄이는 가장 싼 카드.
