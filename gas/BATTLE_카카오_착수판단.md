# 카카오 착수 판단 — 상담톡은 우리가 못 붙인다

> 260822 조사. **결론부터: 상담톡 말고 챗봇으로 간다.**
> ⚠ 이 환경에서 카카오 공식 문서 도메인이 전부 차단돼 원문 확인을 못 했다.
> 아래는 검색 결과 기반이며, **[미검증]** 표시된 것은 붙이기 전에 원문으로 확인할 것.

## 1. 상담톡 — 막혔다

**상담톡은 카카오 공식 딜러사를 통해서만 도입된다. 사업자가 직접 API를 붙일 수 없다.**
딜러사 15개사(인포뱅크·다우기술·LG CNS·휴머스온·NHN Cloud 등). 과금은 **월 고정비 + 상담방당**.

우리가 레이니를 썼던 이유가 이것이었다. 레이니가 딜러사 자리였고, 그걸 끊었으므로
지금 상담톡으로 가려면 **다른 딜러사와 다시 계약**해야 한다. 그리고 계약해도 문제가 남는다:

- 우리 AI가 그 딜러사 시스템 안에서 돌 수 있어야 한다. 레이니에서 안 됐던 그 문제 그대로다.
- 딜러사가 웹훅을 우리 쪽으로 넘겨주는지는 업체마다 다르다 **[미검증]**

## 2. 카카오 웹훅은 라인보다 빡세다

| | LINE | 카카오 |
|---|---|---|
| 응답 시간 제한 | 2초 | **3초** |
| 실패 시 | 재전송(설정으로 끔) | **최초 포함 총 6회 재전송** [미검증] |
| 연속 실패 | — | 웹훅 **비활성화** 처리 [미검증] |

라인에서 2초를 못 지켜 같은 답이 두 번 나갔다. 카카오는 6회까지 때리고, 계속 실패하면
아예 꺼버린다. **어느 경로로 붙이든 "받자마자 200 반환, 응답은 비동기" 구조가 선행조건이다.**
이건 라인 0순위 처방과 같은 일이라 어차피 해야 한다.

## 3. 되는 길 — 카카오톡 채널 챗봇 + 스킬 서버

- **딜러사 불필요.** 우리가 직접 만든다.
- **챗봇 이용요금 무료** (카카오 공식 발표) — 상담톡의 월 고정비+상담방 과금이 없다.
- 스킬 서버는 **HTTP POST + JSON body**. GAS `doPost`로 그대로 받는다.
- 구조: 카카오톡 사용자 → 카카오 챗봇 → **스킬 서버(우리 GAS)** → 응답

즉 **라인브릿지와 같은 모양**이다. 헌법·정본·발송 관문·환자 기억을 그대로 재사용한다.

### 붙이기 전 확인 4가지 (원문 확인 필요)
1. 스킬 응답 제한 시간 — 통상 5초, 콜백 방식으로 연장 가능하다고 알려져 있으나 **[미검증]**.
   우리 AI 응답이 그 안에 안 끝나면 **콜백 방식이 필수**다(먼저 "확인 중" 응답 → 나중에 본답)
2. 비즈 앱 전환·채널 연동 절차
3. 오픈빌더(챗봇 관리자센터) 접근 권한 — 원장 계정으로 되는지
4. 방화벽 IP 허용은 **불필요** (GAS는 ACL을 안 쓴다). 카카오 IP 목록 API는 우리와 무관

## 4. 원장 결정 1건

> **상담톡 딜러사와 다시 계약할 것인가, 챗봇으로 직접 갈 것인가?**

**추천: 챗봇.** 무료이고, 중간에 남이 없고, 라인브릿지 구조를 그대로 쓴다.
상담톡은 "상담원 배정·상담방 관리" 같은 콜센터 기능이 필요할 때 값어치가 있는데
우리는 그게 필요 없다 — 우리 상담원은 AI고, 이어받기는 `^` 토글로 이미 만들었다.

챗봇의 약점: 상담톡처럼 "채널 대화창에서 상담원이 이어받는" 네이티브 UI가 없다.
우리는 슬랙에서 이어받으므로 상관없다.

## 5. 결정 후 순서 (챗봇으로 갈 경우)

1. 원장이 챗봇 관리자센터 접근 확인 → 채널 연동
2. 스킬 응답 제한·콜백 방식 원문 확인 (위 §3 확인 4가지)
3. `doPost` 수신 모듈 — **받자마자 200**, 응답은 비동기
4. 기존 부품 재사용: 발송 전 관문 · 환자 기억 · 캐싱 호출기
5. 테스트 대화 1건 왕복 확인 후 공개

**라인 배선이 끝나기 전에는 시작하지 않는다.** 같은 부품을 두 곳에 동시에 붙이면
어느 쪽이 문제인지 못 가린다.
