# 바비톡 인입 카드 → 모든코디 자동 기입 — 결선 지시 (260829)

> 원장 지시 260829: "슬랙으로 들어온 바비톡 카드가 모든코디에 자동으로 기입되게 해줘."
> 근거는 원장 확정 260829 「모든코디(콜 업무) 개편 안내」 ③ — 인입 카드 건은 아크로드가 먼저 기입,
> 코디는 상담자 칸을 본인 이름으로 바꾸는 것으로 검수 완료.
>
> **클라우드가 만든 것**: 카드 → 기입안 순수 함수 (`gas/babitalk_incall.gs`, 테스트 28케이스 통과).
> **로컬이 할 것**: 그 함수를 허브 doPost에 한 줄 붙이고 재배포. 아래 3단계, 20분.

## 0. 먼저 확인 — 이미 있는 것을 다시 만들지 않는다

모든코디 **기입 경로는 이미 있고 검증됐다**(집PC 세션 260829 01:01 `#아크로드-로그` dry-run 카드).
원장이 손으로 친 `모든코디: 홍길동 / 1234 / 강남언니 / 접합 시험` 을 받아 기입안 카드를 만들고,
스레드에 `ㄱ` 를 치면 실제로 쓰는 구조(큐 2행)다.

이번 작업은 **그 앞단에 파서를 얹는 것**이다. 쓰기 코드는 새로 만들지 않는다.
(DB는 SELECT 전용 원칙이 있고, 쓰기는 워커의 별도 경로다.)

## 1. 파일 붙이기

`gas/babitalk_incall.gs` 를 허브 GAS 프로젝트에 그대로 넣는다. 의존 없음 — `CacheService`만 쓴다.

노출 함수:

| 함수 | 하는 일 |
|---|---|
| `abtParse_(text)` | 카드 → `{kind, name, phone, event, want, option, amount, orderNo}` |
| `abtCodi_(p)` | 파싱 결과 → `{name, chart:'', phone, inflow:'바비톡', counselor:'아크로드', content, needs}` |
| `abtHandle_(text)` | **진입점.** 기입 대상이면 `{fields, command, dedupeKey, kind}`, 아니면 `null` |

기입하는 카드 3종 · 흘려보내는 것들:

| 카드 머리글 | 판정 |
|---|---|
| `[신규 DB 인입 알림]` | 기입 (`db`) |
| `[카톡상담 신규 DB 인입 알림]` | 기입 (`db_kakao`) |
| `[이벤트결제 시술권 판매완료]` | 기입 (`sale`) |
| `[이벤트결제 환불 알림]` | 기입 안 함 — 카드에 고객명이 없다 |
| 광고 라이브·푸시 마감·정산 공지 | 기입 안 함 |
| 여신티켓·네이버·강남언니 카드 | 이 파서 대상 아님 (`other`) |

## 2. doPost에 한 줄

`#cs_인콜`(`C0BG1CADPAR`) 봇 메시지를 받는 자리에서, 강남언니 대조(`aciHandle_`) 옆에 나란히 둔다.

```js
var bt = abtHandle_(text);
if (bt) {
  // (권장) fields를 기존 모든코디 기입 함수에 그대로 넘긴다 — 문자열 왕복이 없어 오독이 없다
  //   <기존기입함수>({name: bt.fields.name, chart: bt.fields.chart, inflow: bt.fields.inflow,
  //                   phone: bt.fields.phone, counselor: bt.fields.counselor,
  //                   content: bt.fields.content});
  // (대안) 원장이 손으로 치던 명령 형식 그대로 — 경로가 이미 검증돼 있다
  //   <기존명령처리기>(bt.command);
}
```

⚠ **대안 경로를 쓸 때 딱 하나 확인**: 차트 미상 자리를 `-` 로 비운 명령
(`모든코디: 홍길동 / - / 바비톡 / …`)이 기존 명령 처리기에서 통하는지 1건 넣어 본다.
`-` 를 차트번호로 읽어버리면 fields 경로를 쓴다.

## 3. 슬랙 `ㄱ` 승인은 없다 — 바로 기입 (원장 확정 260829)

**첫날부터 승인 없이 바로 기입한다.** 판정은 모든코디 화면에서 하는 게 맞다 —
코디가 상담자 칸을 본인 이름으로 바꾸는 게 검수 완료고, 그게 개편 안내 ③의 설계다.
승인 대기 카드를 슬랙에 쌓으면 같은 판정을 슬랙과 모든코디 두 곳에서 두 번 하게 된다.

기존 `ㄱ` 경로는 **원장이 손으로 치는 `모든코디:` 명령용으로 그대로 둔다.** 인입 카드만 건너뛴다.

## 4. 파서가 지키는 규칙 (원장 확정 반영)

- 상담자 칸 = `아크로드`
- 유입 칸 = `바비톡` — 카드 출처가 곧 유입경로라 추정이 아니다. 꼬리표 안 붙는다.
- **차트번호는 비우고, 꼬리표도 안 붙인다.**
  원장 판정 260829: 차트번호는 **진료를 해야 부여된다 — 인입 단계에 없는 게 정상**이다.
  매 건 `(코디 확인 필요): 차트번호` 가 달리면 소음이 되고, 진짜 필요한 꼬리표까지 같이 무시당한다.
  파서가 `fields.chartExpected = false` 를 준다. **허브 기존 기입 경로가 붙이던
  `차트번호(명부에 없음(신환일 수 있음))` 꼬리표를 이 건들에서는 끄는 게 결선의 유일한 손질이다.**
  재구매 환자라 명부에 있으면 대조해서 채우고, 못 찾으면 경고 없이 그냥 비운다.
- 이름·전화가 둘 다 안 읽히면 **기입안을 만들지 않는다.** 카드 형식이 바뀐 것이므로 조용히 물러난다.
- 희망시간·이벤트명이 비면 그 칸만 `(코디 확인 필요)` 꼬리표.
- 기존 이력은 덧붙이기(append)만 — 이건 기존 기입 경로의 규칙 그대로다.
- **UrlFetch 0회.** 차트 줍기로 할당량이 터진 이력(260828)이 있어 파서는 외부 호출을 하지 않는다.
- 같은 카드 재수신은 6시간 안에 한 번만 기입(`abtDedupeKey_` = 종류+전화+주문번호).
  신규DB → 판매완료처럼 같은 고객의 다른 단계는 별건으로 통과한다.

## 5. 검증 (붙인 뒤 그날 안에)

1. 카드 3종이 각각 한 건씩 들어온 뒤 모든코디에 행이 생겼는지 확인. (슬랙 승인 대기 없이 바로)
2. 상담자 칸이 전부 `아크로드` 인지. **차트 빈 칸에 꼬리표가 안 붙었는지.**
3. 환불 알림·광고 공지가 들어온 날 **행이 안 생겼는지** — 이게 더 중요하다(쓰레기 행이 안 생겨야 한다).
4. 같은 고객이 신규DB → 판매완료로 두 번 왔을 때 **행이 2개**(중복 아님) 인지.
