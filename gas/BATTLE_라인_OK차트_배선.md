## 1. 파일 추가

`gas/okchart_queue_client.gs` → 라인브릿지 GAS 프로젝트에 그대로 복사(내용 수정 금지).

## 2. 속성 2개

브릿지 스크립트 속성에:

| 키 | 값의 출처 |
|---|---|
| `OKQ_URL` | 이 PC `C:\acro-gas\_okchart-worker\config.json` 의 `cloud_url` |
| `OKQ_TOKEN` | 같은 파일의 `cloud_token` |

**값을 화면에 출력하거나 git에 커밋하지 말 것.** 복사해서 속성 칸에 바로 붙인다.

## 3. 왕복 1회 실측 (배선 전 필수)

브릿지 편집기에서 임시 함수로 1회만:

```js
function _tmpQueueSmoke() {
  var r = acqQuery_('patient_verify', { chart: '<실재 차트번호>' });
  Logger.log(r === null ? 'NULL — 아래 진단표 참조' : JSON.stringify(r).slice(0, 300));
}
```

- 왕복 약 60초. 결과가 나오면 **응답 필드명(sn/name 등)을 눈으로 확인**하고 다음 단계로.
- 확인 끝나면 이 임시 함수는 지운다.

### NULL이 나올 때 진단표

| 확인 | 방법 |
|---|---|
| 속성 오타 | `OKQ_URL`·`OKQ_TOKEN` 철자·앞뒤 공백 |
| 워커 정지 | PC에서 워커 프로세스 살아 있는지 |
| 야간(22~09시) | 워커 폴링 300초라 상한(180초) 안에 못 온다 — **정상이다.** 주간에 다시 |
| 큐 웹앱 | `named_query` 이름이 워커에 등록돼 있는지 (`patient_verify`는 등록돼 있음) |

## 4. 배선 지점 — 딱 한 곳

환자 메시지로 **AI 응답을 만드는 그 함수** 안, **프롬프트를 조립하기 직전**.

```js
// 차트번호로 본인이 특정된 대화에서만. 아니면 조회하지 않는다.
var ctx = chartNo ? acqPatientContext_({ chart: chartNo }) : '';
// 프롬프트에서 환자 메시지 **앞**에 붙인다
var userBlock = (ctx ? ctx + '\n\n' : '') + '## 환자 메시지\n' + 환자메시지;
```

`acqPatientContext_`가 돌려주는 것(예):

```
## 환자 실측(전산 · 내부 재료 — 원문을 환자에게 노출 금지)
환자 확인: 재진(전산 기록 있음)
최근 진료: [{"TxDate":"2026-08-01","px":"다이어트재진"}]
예약: [{"Res_Time_0":"14:00"}]
```

**규칙 3개 (어기면 사고):**
1. **본인 확인된 대화만 조회.** 차트번호를 모르면 `ctx`는 빈 문자열 — 조회하지 않는다.
2. **조회 원문을 환자에게 보내지 않는다.** 이건 AI가 읽는 재료다(헌법 4 — 환자 사이의 벽).
3. **실패는 조용히.** `acqPatientContext_`는 실패 시 빈 문자열을 준다 — 그대로 평소처럼 답하면 된다. 환자에게 "조회 중입니다"·"오류" 같은 말을 하지 않는다.

## 5. 검증 2개 (통과 전 배포 금지)

| # | 방법 | 통과 기준 |
|---|---|---|
| 1 | 차트번호가 확인된 **재진** 환자로 테스트 대화 | "처음 오시나요?"를 **묻지 않고**, 최근 진료를 아는 티가 나는 응대 |
| 2 | 워커를 **끈 상태**로 같은 대화 | 지연·오류 노출 없이 평소처럼 응대(느려지되 답은 나온다) |

2번이 이 배선의 안전판이다 — 큐가 죽어도 응대는 죽지 않아야 한다.

## 불변 (전 과정)

- DB는 **SELECT만**. INSERT/UPDATE 어떤 경로로도 금지.
- 토큰·URL 값은 화면 출력·커밋 금지.
- 환자 실명·차트번호는 원내 채널 한정. 공개 리포에 남기지 않는다.
- 실패·거부는 전부 조용히 넘기고 사람에게 인계 — 지어내지 않는다.
