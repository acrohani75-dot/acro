# 아크로드 세션 운영 — 어디서 무엇이 되는가

작성 260725. 아크로드 작업을 **어느 Claude 환경에서 착수해야 하는지** 판단하는 표.
착수 전에 이 표를 먼저 본다. 안 되는 환경에서 시작하면 중간에 막히고, 그 세션의 컨텍스트는 버려진다.

## 1. 환경 3종

| | 웹 세션 (claude.ai/code) | 로컬 Claude Code (맥/윈도우 앱·터미널) | Cowork |
|---|---|---|---|
| 실행 위치 | 클라우드 컨테이너(휘발성) | 그 창이 떠 있는 PC (201PC·진료실PC·집PC 중 하나) | 클라우드 |
| 리포 | 세션 시작 시 fresh clone | 로컬 폴더 그대로 | — |
| 커밋 안 한 파일 | **세션 종료 시 소멸** | 남는다 | — |

npm 레지스트리는 프록시 예외라 `npm i -g @google/clasp`는 되지만, **`clasp login`이 안 되므로 배포는 불가**하다.

## 2.5 컴퓨터 2대 + 창 4종 시대의 지도 (260820 갱신)

원장이 PC 2대(집·병원)에서 Cowork와 Claude Code를 섞어 쓰면서 "어느 창이 어디에
연결되는지" 헷갈리는 문제가 생겼다. **창의 종류가 능력을 정하지, 컴퓨터가 정하는 게 아니다** —
단, PC에 깔린 열쇠(clasp·워커)만은 그 PC에 묶인다.

| 창 | 정체 | 잘하는 것 | 못하는 것 |
|---|---|---|---|
| **CODE 로컬** (201PC·진료실PC·집PC의 터미널/데스크톱 앱) | 그 PC에서 직접 실행 | **clasp 배포(배선)** · 그 PC의 파일 · git push | 그 PC에 없는 열쇠 (예: 워커는 원내 PC에만) · 201PC 기본 창은 일반권한이라 서비스 조작 불가 |
| **CODE 웹** (claude.ai/code) | 클라우드 컨테이너 | 리포·정본·KB 등재 · Slack/Drive/Notion 대조 · 설계 | **clasp 배포 불가** · PC 파일 불가 |
| **Cowork** | 클라우드 허브 | Slack 실측·운영 감시 · 대량 반복 위임 | 리포 직접 pull 불가(환경에 따라) · clasp 불가 |
| **예약 루틴** (모든코디·처방전 등) | 클라우드 자동 세션 | 정해진 정기작업 | 그 외 전부 — 말 걸어도 못 알아듣는다 |

**판별 질문 하나면 된다: "이 일이 PC 안의 무언가(clasp·워커·로컬 파일)를 만지는가?"**
- 만진다 → 그 열쇠가 있는 PC의 **CODE 로컬** (배선·배포·워커 설치)
- 안 만진다 → 아무 데서나 되지만, 역할 분담은: 지식·설계·리포 = **CODE 웹**, 슬랙 실측·감시 = **Cowork**

### PC 호칭 — 3대다 (원장 확정 260830)

한의원에 Claude가 깔린 PC가 3대라 "한의원PC"로는 구분이 안 된다. **그 호칭은 폐기한다.**

| 호칭 | 정체 | 특기사항 |
|---|---|---|
| **201PC** | OK차트 DB 서버 본체 | 기본 Claude 창이 **일반권한** — 서비스 중지·재시작 등 상태 변경이 안 된다 |
| **진료실PC** | 진료실 데스크 (구 "한의원PC") | |
| **집PC** | 원격 관제 | |

- 구 표기 "병원 PC"·"한의원PC"를 보면 **201PC인지 진료실PC인지 다시 확인하고 쓴다.** 둘은 다른 자리다.
- 201PC에는 **SQL 인스턴스가 2개** 있다 — `MSSQL$OKCHART`(우리 것)와 `MSSQL$IEMBIO`(별개, 건드리지 않는다).
- 상세는 Drive 지식인입함(`90_지식인입함`)에서 **`PC구성및호칭_운영문서`** 를 title로 검색.
  (이 리포는 public이라 Drive 링크·파일 ID는 적지 않는다.)

열쇠의 위치 (260820 기준 · 호칭 260830 갱신):
- **원내 PC**: OK차트 워커(`C:\acro-gas`) + 큐 config.json — DB가 원내 LAN이라 여기 고정.
  ⚠ **201PC인지 진료실PC인지 `___[확인 필요]`.** 옛 문서의 "병원 PC"를 3대 체계로 옮기다 만
  자리다. 추측으로 채우면 "워커가 안 돈다" 할 때 사람이 엉뚱한 PC 앞에 간다.
- **clasp 로그인**: Google 계정 단위라 **두 PC 모두 가능** — `clasp login` 한 번씩 해두면
  어느 PC에서든 배선이 된다 (브릿지 소스 폴더는 pull 받으면 됨)
- **커넥터(Slack·Drive 등)**: 대화 **시작 시점에 고정** — 중간에 켜면 그 대화에선 안 잡힌다.
  새로 켰으면 새 대화를 열 것 (CLAUDE.md §4와 동일)

**세션 간 전달 규칙**: 말로 옮기지 말고 **리포에 적는다.** 배선 지시는 `gas/BATTLE_배선_인계.md`,
지식은 acro_canon — 어느 창이든 pull 하면 같은 것을 본다. 사람이 복붙으로 나르는 순간부터
버전이 갈라진다.

## 3. 그래서 작업 분담

- **웹 세션**: 정본 md 작성·이관 검수, KB 스키마 설계, 리포 산출물 수정, Slack/Drive 대조, 문서화, 리포 PR.
- **로컬 세션**: clasp 셋업, 빌드 GAS 작성·배포, 역빌드 diff 검증, OK차트 자동화, 저널 원문 확인.
- **Cowork**: 위임 브리프 기반 L2 이관 같은 대량 반복 작업.

## 4. 실패 이력 — 되풀이 금지

| 시도 | 결과 | 결론 |
|---|---|---|
| 크롬 익스텐션 브릿지로 대용량 주입 (165KB) | 2회 동일 지점 붕괴 | 브라우저 주입으로 돌아가지 않는다. 경로를 clasp로 바꿔 문제를 제거 |
| "계정 통일이 빌드의 전제조건" | **과장, 철회** | 필요한 건 소유권 일치가 아니라 **접근 권한**. GAS는 실행 계정 권한으로 돈다 |
| DOI로 자체 논문 서지 확정 (웹 세션) | 실패 | 해당 저널은 **PubMed 비색인**이고, doi.org·crossref는 웹 세션에서 차단. → 로컬 세션 또는 저널 원문 PDF로만 확정 가능 |

권한 관련 안전장치: 빌드 GAS 첫 단계에 **"정본 폴더 읽기 시도 → 실패 시 슬랙 경보"**. 권한이 끊겨도 조용히 실패하지 않게 한다.

## 5. 착수 순서 (기획 정본 §5 요약 — 상세는 Drive 정본)

1. clasp 셋업 (Apps Script API 켜기 → node 확인 → clasp 설치 → login) — **로컬**
2. L2 이관 a~d — Cowork 위임. 완료조건: KB 건수 = 원본 행 수(누락 0 증명)
3. 빌드 GAS 작성 — clasp 경유. 권한 자가진단 포함
4. 역빌드 검증 — 정본에서 컴파일한 결과 vs 현행 시트 **diff 0**. 통과 전 전환 금지
5. 전환 + 드리프트 감시 가동
6. L3 파일럿 1도메인 (전 자산 일괄 색인 금지)
7. 실패 회수 루프 연결

## 6. 판단 원칙

- **RAG는 절대 1순위가 되지 않는다.** 정본 히트 우선, 미스일 때만 RAG 보조. (구가격 오염 차단)
- 다음 모델 업데이트를 기다리며 착수를 미루지 않는다. 현재 능력의 바닥선에서 돌아가게 짓는다. 모델이 바뀌어도 두뇌는 남는다.
- 잘 지어질수록 커 보여야 하는 건 시스템이 아니라 **아크로한의원**이다. 그게 성공 판정 기준이다.
